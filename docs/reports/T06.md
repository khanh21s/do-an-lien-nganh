- **AUTH-01 refresh queue** (`30427a9`): `lib/api.ts` has a pure `createRefreshQueue()` (concurrent callers share one in-flight promise) and `attachAuthInterceptors(instance, deps)` with injectable deps. Every request gets a Bearer header. A 401 triggers refresh then one retry. The retry re-reads the current token, so a request that raced another refresh just retries. Refresh goes through a bare axios client and never re-enters the interceptors. `/auth/login|register|refresh-token` never refresh. If refresh fails, the store is cleared and the user is sent to `/login?next=…`. The store gained `setTokens`. Test: `lib/api.refresh.test.ts`.
