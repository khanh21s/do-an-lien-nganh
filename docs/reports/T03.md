# T03 – practice-service: report

Branch: `feat/T03-practice` (base `47c8301`).

## What changed
- **DIC-07** `DictationScorer.weightedScore`: weights Easy 0.6 / Normal 0.8 / Hard 1.0 (null/unknown → Normal), rounded to 2 decimals, clamped to [0, 100]. `normalize` is now `public static` so the mock scorer can reuse it.
- **Storage** (`service/storage/`): `RecordingStorage` interface + `S3RecordingStorage` (presigned PUT signed with `Content-Type: audio/wav`, same as before) + `LocalRecordingStorage` (`${MEDIA_ROOT}/shadowing/<userId>/<recordingId>.wav`, atomic write, path-traversal guard). `config/StorageConfig` creates exactly one bean based on `app.storage.provider` (auto/s3/local); S3 clients are only built in s3 mode. The old `S3Config` and `ShadowingStorageService` are removed.
- **Speech** (`service/speech/`): `PronunciationScorer` interface; `AzureSpeechClient` (moved, implements it, keeps `audio/wav; codecs=audio/pcm; samplerate=16000`, NoMatch → 400 in Vietnamese, also reads the flat score layout); `MockPronunciationScorer` as described in architecture §8.2 (20 ms frames, RMS threshold 0.02, < 10 % voiced → 20–40, otherwise `60 + 35 × voicedRatio ± 7`, phoneme groups ±5). `config/SpeechConfig` picks the scorer based on `app.speech.provider`.
- `config/ProviderSelection`: logic for auto/explicit selection (`your_…` placeholders count as missing; an explicit s3/azure without keys makes startup fail). `ProviderStartupLogger` writes one line at startup: `Storage provider: local (MEDIA_ROOT=/data/media) | Speech provider: mock`.
- `util/WavUtils`: RIFF chunk parser (skips LIST/JUNK, tolerates data size 0/0xFFFFFFFF, WAVE_FORMAT_EXTENSIBLE with a PCM subformat); `validate` requires PCM, 16 kHz, mono, 16-bit, 0.5–30 s → 400 "Định dạng ghi âm không hợp lệ (cần WAV PCM 16 kHz mono)" / "Bản ghi phải dài từ 0,5 đến 30 giây".
- **Endpoints**
  - `POST /practice/shadowing/request-upload-url` adds `uploadMethod`, `uploadRequiresAuth`, `contentType`, `storage`.
  - NEW `PUT /practice/shadowing/recordings/{recordingId}`: local only (s3 → 404), recordingId must be a UUID (otherwise 400), body is read with a hard 2 MB cap, WAV is validated → 204.
  - `POST /practice/shadowing/attempt`: validates the recordingId and WAV before scoring, adds `scorer`; when `duration` is missing it falls back to the WAV length. No longer `@Transactional`, so the Azure call does not hold a DB connection.
  - `GET /practice/shadowing/{attemptId}/recording`: uses `findByIdAndUserId` → 404 if the recording belongs to another user (SHA-04).
  - NEW `GET /practice/stats/activity?days=` (1–365, default 90, out of range or not a number → 400): native query grouped by `to_char(created_at AT TIME ZONE 'Asia/Ho_Chi_Minh','YYYY-MM-DD')`, empty days filled in, `minutes = round(sum(duration)/60)`.
  - Streak (PRA-07) and the weekly trend in `/practice/stats` now bucket days in Vietnam time (`util/AppTime.ZONE`).
  - `AttemptSummaryResponse` + `difficulty` (PRA-05).
- **Pre-existing bug found by the smoke test**: `GET /practice/attempts` without `lessonId` returned 500 (Postgres: "could not determine data type of parameter $2" for a null UUID in `:lessonId IS NULL`). This also affected `trending-errors`. I replaced it with dispatch to derived queries and clamped `page ≥ 1`, `limit 1–100`.
- `GlobalExceptionHandler`: `MethodArgumentTypeMismatch` / `HttpMessageNotReadable` → 400; Spring MVC's own errors (404/405/415…) keep their status instead of becoming 500; unhandled errors are now logged with the requestId.
- `application.yml`: only adds an `app:` block at the end of the file (`storage.provider`, `storage.local-root`, `speech.provider`).

## Cross-task requests
- **T02 (SecurityConfig)**: `/error` is not permitted, so any exception that escapes the controller advice (for example a body Tomcat cannot parse) gets 401 "Authentication required" instead of its real status. Suggest `.requestMatchers("/error").permitAll()` or `dispatcherTypeMatchers(DispatcherType.ERROR).permitAll()`.
- **T02 (application.yml `spring:`)**: when a client sends PUT without a `Content-Type`, curl defaults to `application/x-www-form-urlencoded`. Spring's `FormContentFilter` then tries to decode the WAV body as a form and fails. Suggest `spring.mvc.formcontent.filter.enabled: false` for practice-service. Clients that follow the contract (`Content-Type: audio/wav`) are not affected.
- **T01**: compose needs to pass `STORAGE_PROVIDER`, `SPEECH_PROVIDER`, `MEDIA_ROOT` and mount the `media_data` volume at `/data/media` for practice-service, owned by `appuser` (already in the contract, §8.4). `AWS_S3_BUCKET` is required when using s3.
- **T06/T09 (FE)**: the new fields `uploadMethod/uploadRequiresAuth/contentType/storage`, `scorer`, `AttemptSummary.difficulty`, and `ActivityDay {date, attempts, minutes}` follow §4.5.

## Risks / notes
- The mock score only measures how much of the recording has voice; it is not real pronunciation scoring. The FE must show the "Chế độ demo" badge.
- Local mode does not track which recordingIds were issued. A user can PUT any UUID, but only into their own folder; re-PUTting the same id overwrites the file. Files are never cleaned up.
- Stats are still cached for 1 h (`practice:stats:*`), so `currentStreak` in `/practice/stats` can lag by up to 1 h across midnight. `/practice/streak` is not cached.
