# T04 – content-service report

Branch: `feat/T04-content` (created from 47c8301 as instructed; tasks.md names it `feat/T04-content-backend`).

## What changed
- `service/storage/`: `LessonAudioStorage` (interface), `LocalLessonAudioStorage`, `S3LessonAudioStorage`,
  `RoutingLessonAudioStorage` (the single bean; reads routed by value prefix), `StorageProvider` (auto/s3/local),
  `AudioFormats` (ext → Content-Type, upload validation), `ByteRange` (RFC 7233 single range, 206/416).
- `config/StorageConfig.java` replaces `config/S3Config.java`; `S3Client` only built in s3 mode.
  `service/S3StorageService.java` removed. Startup log: `Storage provider: local (MEDIA_ROOT=/data/media)`.
- `application.yml`: multipart `max-file-size: 50MB`, `max-request-size: 51MB` (1MB headroom for multipart
  overhead so a full 50MB file is accepted); new `app.storage.{provider,local-root}` block at end of file.
- `LessonService`: `evictLessonCaches(lessonId)` (after commit) for create/update/delete lesson, add/update/delete
  sentence, upload audio; `updateSentence` (partial, merged startMs<endMs check, optional reorder) and
  `deleteSentence` (renumber 1..N in same transaction). Upload: validate → store new → save → delete old after commit
  (seed files under `local:seed/` are never deleted).
- `LessonController`: `PUT/DELETE /lessons/{id}/sentences/{sentenceId}` (admin; 404 if sentence not in lesson).
- `GlobalExceptionHandler`: `MaxUploadSizeExceededException` → 400, missing multipart part → 400.

## Tests (27, all green)
`LocalLessonAudioStorageTest` (store/read/Range/416/traversal/delete), `StorageSelectionTest` (provider resolution,
upload validation, routing 404), `LessonServiceSentenceTest` (delete 2/5 → 1..4, reorder, timing validation,
cache eviction, upload flow).

## Notes / risks
- `CacheService.invalidateByPattern` still uses `KEYS` (owned by T02, X-06 → SCAN).
- Uploads above 50MB: Tomcat `server.tomcat.max-swallow-size` (default 2MB) may reset the connection instead of
  returning the 400 body; the `server:` block is not owned by T04.
- No Spring-context test (no DB/Redis in unit tests per architecture §9); bean wiring verified by compile only.
- E2E ACs (20MB upload via gateway, seed `local:seed/...` playback, 403 for non-admin) need T01 compose
  (`media_data` volume, `./media/seed` mount, `STORAGE_PROVIDER`/`MEDIA_ROOT` env) and are not run here.
