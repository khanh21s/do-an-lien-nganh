# T02 – Coder notes

Branch: `feat/T02-security` (base `47c8301`).

## Changes
- **Gateway**: `middleware/auth.js` exits(1) when `JWT_SECRET` is missing or < 32 bytes, accepts only `type=access` and HS256, checks `token_blacklist:{jti}` through the new `middleware/redis.js` (node-redis 4.6.14, `REDIS_URL`, lazy connect, `disableOfflineQueue`, at most 500 ms wait, fail-open + WARN). `server.js` makes `/subscriptions/vnpay-ipn` public. `package.json` versions are pinned exactly, `package-lock.json` is committed, and the Dockerfile uses `npm ci --omit=dev`.
- **Java (5 services)**: `JwtValidator`/`JwtService` throw `IllegalStateException` when the secret is empty or < 32 bytes. They add `parseAccessToken()` (type must be `access`). `JwtAuthFilter` uses it, rejects tokens without a `jti` and checks the blacklist (a Redis `DataAccessException` fails open + WARN). In `application.yml`, `jwt.secret: ${JWT_SECRET:}` has no default, and `internal.token: ${INTERNAL_TOKEN:}` sits right below `jwt:`.
- **X-02**: `InternalTokenFilter` (auth, subscription) matches only `/internal` + `/internal/**` on the decoded servlet path. It compares the SHA-256 digests with `MessageDigest.isEqual` and returns a 401 with the standard JSON body. A blank token fails startup; a token shorter than 32 chars only logs a WARN. It is registered in `SecurityConfig` before the JWT filter.
- **SUB-02**: subscription `SecurityConfig` permits `GET /subscriptions/vnpay-ipn`.
- **X-06**: `CacheService.invalidateByPattern` uses SCAN (count 500) + DEL in batches of 500 (4 services).
- **AUTH-04**: Google/Apple return 503 "Google/Apple login chưa cấu hình" when the client id is blank, before any network call. `aud` is always checked (Apple uses `aud.contains`).
- **AUTH-07**: `changePassword` returns 400 "Tài khoản đăng nhập bằng Google/Apple không có mật khẩu" when `authProvider` is not `email`/`local` (local accounts are stored as `email`).

## Tests
`auth-service`: `JwtServiceTest` (5), `InternalTokenFilterTest` (5) and `SocialLoginAndPasswordTest` (4) all pass.
Gateway smoke test (real Redis, throwaway docker network):
- No token / refresh token / blacklisted jti on practice, vocabs/user and subscriptions → 401.
- Access token and `/subscriptions/vnpay-ipn` without a token → proxied (502, no backend running).
- `/internal/*` → 404.
- With Redis unreachable: fail-open, proxied.

## Cross-task requests
- **T05**: `subscription/service/AuthServiceClient` and `vocabulary/service/PremiumClient` must send `X-Internal-Token: ${internal.token}`. Without it, subscription→auth and vocabulary→subscription `/internal/**` calls now get 401 (PremiumClient fails closed, so it treats the user as non-premium).
- **T01**: compose/.env must set `JWT_SECRET` (≥ 32) for gw + 5 services, and `INTERNAL_TOKEN` at least for auth and subscription (both fail startup without it) and for vocabulary (needed for its calls). Set `REDIS_URL=redis://redis:6379` for the gateway.

## Risks
- Java blacklist fail-open relies on the Lettuce command timeout (default 60 s). If Redis hangs instead of refusing connections, requests may stall. Consider setting `spring.data.redis.timeout` (not a T02 block).
- Tokens without `jti` are now rejected everywhere, GW included (auth always issues one).
