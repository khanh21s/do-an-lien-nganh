# T05 – vocabulary-service + subscription-service: report

Branch `feat/T05-vocab-sub` (from `47c8301`).

## Done

### vocabulary-service
- **VOC-01** `SM2Calculator`: standard SM-2 (architecture §4.6), returns `{interval, easeFactor, repetitions}`. q<3 resets reps to 0 and sets interval 1; n=0 → 1, n=1 → 6, n>1 → round(I×EF_old). EF uses exact `BigDecimal` math, HALF_UP 2 decimals, floor 1.30. `ReviewService.submitReview` stores the result; `next_review_at = now + interval days`; message depends on rating/interval.
- **VOC-03** `addFromLesson`: card in an `isProOnly` deck and user not premium → 403 "Bộ từ Pro – nâng cấp Premium để học".
- **X-02 (client side)** `PremiumClient` sends `X-Internal-Token: ${internal.token:}`. It keeps the `premium:{userId}` key. A failed lookup is no longer cached (it used to cache `false` for 5 minutes).
- **VOC-04** `GET /vocabs/decks/{id}/cards` sets `userVocabId` when there is a principal, using one `IN` query. Authenticated requests skip the shared (user-independent) deck-cards cache.
- **VOC-07** `ReviewQueueItem` adds `exampleVi, partOfSpeech, audioUrl, imageUrl`. The review-queue query fetch-joins the card.
- **ADM-05** `DELETE /vocabs/cards/{id}` (admin) → `{message}`. It recounts `card_count` in the same transaction and evicts the deck caches.
- **ADM-07** `createDeck` sets `created_by = principal.userUuid()`.

### subscription-service
- **SUB-01/02** `VNPayService.verifySignature` is a pure, constant-time check. `sign()` is shared with URL building. `SubscriptionService.processVnpayResult` serves both IPN and return URL: 97 / 01 / 02 (row lock `PESSIMISTIC_WRITE`, only `pending` rows change) / 04 (marks `failed`) / 00. A transaction succeeds only when `vnp_ResponseCode` and `vnp_TransactionStatus` are both `00`. `GET /subscriptions/vnpay-ipn` → `{RspCode, Message}` (unexpected error → 99). `payment-callback` runs the same idempotent processing, then only redirects.
- **SUB-04** `PremiumCacheEvictor` runs `DEL premium:{userId}` after commit for both payment and code activations. Redis errors are logged, not thrown. The confirmation email is also sent after commit.
- **SUB-05** activate-code: code is trimmed and upper-cased, row is locked. Errors: unknown → 404 "Mã không hợp lệ", used → 400 "Mã đã được sử dụng", expired → 400 "Mã đã hết hạn". Time accumulates (`end_at += duration` while active).
- **ADM-06** `security/AdminGuard` (`admin.emails`, new `admin:` yml block, default `admin@parroto.com` like vocabulary-service). `POST /subscriptions/admin/activation-codes`:
  - body `{planId, quantity 1–500, expiresAt?}`; `expiresAt` accepts ISO date-time or `YYYY-MM-DD` (end of day, VN time), defaults to now+365d, and a past date → 400.
  - generates `PROMO-XXXXX-XXXXX` codes from `A–HJ–NP–Z2–9`, unique within the batch and against the DB, retrying on collisions.

  `GET /subscriptions/admin/activation-codes?used&page&limit` returns `PageResponse<ActivationCode>`. `usedByEmail` comes from `AuthServiceClient`, which sends `X-Internal-Token` and returns null on error.
- `GlobalExceptionHandler`: malformed JSON or bad query param type → 400 (was 500).

## Risks / notes
- Concurrent `addCards` and `deleteCard` on the same deck: `card_count` is recounted (not decremented), so it converges.
- `activate-code` on an unknown code now answers 404 "Mã không hợp lệ" and a used code answers 400 instead of the old 409 (per contract). FE must not depend on the old messages.
- `createPayment` still rejects users who are already premium (409, existing behaviour). Only codes accumulate from the UI path.
